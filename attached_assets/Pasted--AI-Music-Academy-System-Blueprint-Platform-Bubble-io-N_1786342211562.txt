## 1. EXECUTIVE SUMMARY

AI Music Academy is a two-sided music streaming and artist monetization platform built on Bubble.io. Artists upload AI-generated music, sell merchandise, and earn per-play stream revenue. Listeners stream music, follow artists, engage in a public community, and browse merch.

**Platform Type:** Software as a Service (SaaS)
**Target Users:** AI music artists (creators) + music enthusiasts (listeners)
**Revenue Model:** Recurring monthly subscriptions (both sides)

---

## 2. BUSINESS MODEL

### Revenue Sources
- **Listener subscriptions:** $6.99/mo (Basic) or $14.99/mo (Pro)
- **Artist subscriptions:** $49.99/mo (Basic, 1 merch slot) or $99.99/mo (Pro, 3 merch slots)

### Non-Revenue Streams
- **Merchandise:** External fulfillment (Printful/Shopify/Etsy) via direct `buy_link` per product. No platform cart, no commission, no transaction fees — artists retain 100% of merch revenue.
- **Stream earnings for artists:** Small per-play payout tracked via internal ledger. Artists request withdrawals; operator processes payouts manually via admin dashboard.

### Not Included
- No advertising revenue
- No data monetization
- No transaction fees on merch
- No cart / checkout on platform (external only)

## 4. USER ROLES & ACCESS CONTROL

### Roles

| Role | Identifier | Access Level |
|---|---|---|
| **Guest** | Not logged in | Public pages only |
| **Listener** | `user_type = "LISTENER"` | Music streaming, community, merch browsing, profile |
| **Artist** | `user_type = "ARTIST"` | All Listener access + upload, merch selling, analytics, earnings |
| **Admin** | `is_admin = yes` | Full backend access (users, moderation, payouts) |

### Access Rules Per User Type

**Guests can access:**
- Homepage, login, signup, subscription selection, legal pages, forgot/reset password
- Cannot access any dashboard, streaming, community, or admin pages

**Listeners can access:**
- All Listener pages (Browse Music, My Library, Browse Merch, Community, My Profile)
- Public artist profiles (view-only)
- Cannot access Artist dashboard, upload, merch management, analytics
- Cannot access any Admin page

**Artists can access:**
- All Listener pages (they can consume the platform too)
- All Artist pages (Dashboard, Analytics, Merch Store, Cover Art, Upload, Releases, Profile)
- Cannot access any Admin page

**Admins can access:**
- All Admin pages (Dashboard, Users, Moderation, Payouts)
- Can view all user data (via admin privacy rule)
- Admins log in through the same `login` page — access is unlocked by `is_admin = yes` on the User record
- Non-admin users are server-side redirected out of admin pages

### Enforcement Methods
1. **Server-side page redirects** — every gated page checks `Current User` conditions on page load; wrong-role users are redirected to appropriate landing page
2. **Privacy rules** — Bubble database-level rules restrict what data each user role can query (see Section 9)
3. **Workflow conditions** — sensitive workflows check role before executing

## 5. SUBSCRIPTION TIERS

All subscriptions are monthly, cancel anytime, processed via Stripe.

| Plan | Price | Role | Benefits |
|---|---|---|---|
| **Listener Basic** | $6.99/mo | Listener | Ad-free streaming, standard quality audio, public community access |
| **Listener Pro** | $14.99/mo | Listener | HQ audio, offline downloads, exclusive artist content, priority support |
| **Artist Basic** | $49.99/mo | Artist | Unlimited track uploads, 1 active merch slot, analytics, AI cover art generator, community |
| **Artist Pro** | $99.99/mo | Artist | All Basic features + 3 active merch slots |

### Payment Flow
1. User signs up → selects role → chooses plan
2. Clicks plan → external redirect to Stripe Payment Link with `?client_reference_id=[User's unique ID]`
3. Stripe processes payment → redirects user back to `subscription_success` page
4. Stripe fires `checkout.session.completed` webhook to `stripe_webhook` backend endpoint
5. Webhook matches user by `client_reference_id`, sets subscription fields
6. Success page polls `has_onboarded` → redirects to dashboard when true

### Subscription Management
- **Manage/Cancel:** User clicks "Manage Subscription" on profile → API call to Stripe Customer Portal → redirect to Stripe-hosted portal for card updates, cancellation, invoice history
- **Failed payments:** Stripe fires `invoice.payment_failed` → `subscription_status` set to `"past_due"`
- **Cancellation:** Stripe fires `customer.subscription.deleted` → `subscription_status = "canceled"`, `has_onboarded = no`

## 9. PRIVACY & SECURITY RULES

Bubble enforces data access at the database level via Privacy Rules. Every data type has role-based restrictions.

### User
| Rule | When | Fields |
|---|---|---|
| Everyone else | Default | Public fields only: `artist_name`, `bio`, `profile_image`, `cover_image` |
| User's own record | `This User is Current User` | All fields |
| **Admin override** | `Current User's is_admin is yes` | All fields + Find in searches |

Without the admin override, admin RepeatingGroups return empty data.

### Track
| Rule | When | Fields |
|---|---|---|
| Public tracks | `This Track's is_published is yes` | All viewable |
| Creator | `This Track's artist is Current User` | Full access + edit/delete |
| Admin | `Current User's is_admin is yes` | Full access |

### Merch_Product
| Rule | When | Fields |
|---|---|---|
| Active products | `This Merch_Product's is_active is yes` | All viewable |
| Creator | `This Merch_Product's artist is Current User` | Full access + edit/delete |
| Admin | `Current User's is_admin is yes` | Full access |

### Post & Comment
| Rule | When | Fields |
|---|---|---|
| Logged-in users | `Current User is logged in` | All viewable |
| Creator | `This Post's author is Current User` | Edit/delete own |
| Admin | `Current User's is_admin is yes` | Full moderation access |

### Report
| Rule | When | Fields |
|---|---|---|
| Reporter | `This Report's reporter is Current User` | View own reports |
| Admin | `Current User's is_admin is yes` | Full access |

### Banned_Word
| Rule | When | Fields |
|---|---|---|
| Admin only | `Current User's is_admin is yes` | Full access |

### Play_History
- **No user-facing privacy rule.** Only accessed via backend workflow `play_increment_balances` which uses "Ignore privacy rules" to bypass restrictions and update artist balances.

### Additional Security
- **Server-side redirects** on all gated pages (checked on page load via workflow)
- **`is_banned = yes` check** on login → banned users get logout + error
- **Password reset** via Bubble's built-in secure token flow
- **API keys stored in Bubble Backend Workflows** (Stripe secret key, OpenAI key) — never exposed to frontend

## 10. THIRD-PARTY INTEGRATIONS

### Stripe (Payments)
**Setup:** API Connector with Bearer auth + `Content-Type: application/x-www-form-urlencoded` shared header

**Products (4 Payment Links):**
- Listener Basic ($6.99)
- Listener Pro ($14.99)
- Artist Basic ($49.99)
- Artist Pro ($99.99)

**Webhook Events Subscribed:**
- `checkout.session.completed` — activates subscription
- `customer.subscription.updated` — handles plan changes
- `customer.subscription.deleted` — cancels subscription
- `invoice.payment_failed` — sets past_due status

**API Calls Configured:**
- Create Customer Portal Session (POST)
- Cancel Subscription (DELETE)

**Critical Note:** Bubble's Form-data body type sends `multipart/form-data` which Stripe rejects. Use Body type "JSON" and manually write `key=value` pairs.

### OpenAI (AI Cover Art)
